RECAP

This table stores all notifications created in your system. Think of it as “a log of all events that users should be notified about.”

| Field              | Type             | Description                                                                                                                                                                                                                    |                                                                                                                                                                                                                                                                       |
| ------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`             | `string`         | The **category of the notification**. You have three types: `DEMANDE` (for demandes), `FACTURE` (for invoices), `ANNONCE` (for announcements). This helps filter or group notifications.                                       |                                                                                                                                                                                                                                                                       |
| `event`            | `string`         | A **specific event within the type**. Example: `NOUVELLE_DEMANDE`, `NOUVEAU_COMMENTAIRE`, `ANNONCE_PUBLIQUE`, `ANNONCE_PRIVEE`. This tells the frontend exactly what action occurred.                                          |                                                                                                                                                                                                                                                                       |
| `source_user_id`   | `ObjectId`       | The **user who triggered the notification** (created a demande, posted a comment, created an annonce, etc.).                                                                                                                   |                                                                                                                                                                                                                                                                       |
| `target_roles`     | `array<string>`  | The **roles who should see this notification**. Possible values: `ADMIN_CENTRE`, `ADMIN_BOUTIQUE`, `ACHETEUR`. If the role of the source_user matches one of these, that role is **excluded** from receiving the notification. |                                                                                                                                                                                                                                                                       |
| `target_boutiques` | `array<ObjectId> | null`                                                                                                                                                                                                                          | Optional. Used when the notification is meant for **admins of specific boutiques**. Example: if an admin centre creates a demande targeting a boutique, all admins of that boutique should be notified, so their boutique IDs go here. Null if it’s global to a role. |
| `message`          | `string`         | The **content** of the notification. Could be the demande description, comment text, or announcement summary.                                                                                                                  |                                                                                                                                                                                                                                                                       |
| `created_at`       | `date`           | When the notification was **created**. Useful for sorting, displaying “new notifications,” or expiration logic.                                                                                                                |                                                                                                                                                                                                                                                                       |


notifications are always created, even if no one has read them yet.

They contain all the information needed to deliver to the right users or roles.

You can filter notifications by target_roles and optionally by target_boutiques.

Table: notification_reads

This table tracks which users have read which notifications. This is how you implement “seen” logic for group notifications.

| Field             | Type       | Description                                                 |
| ----------------- | ---------- | ----------------------------------------------------------- |
| `notification_id` | `ObjectId` | Reference to the **notification in `notifications` table**. |
| `utilisateur_id`  | `ObjectId` | The **user who has read this notification**.                |
| `read_at`         | `date`     | The **timestamp when the user read the notification**.      |

Key logic:

Every time a user views a notification, you create a record in notification_reads.

To know unread notifications for a user:

unread = notifications where notification_id NOT IN (notification_reads for this user)

For group-read notifications (like “if one admin of a boutique reads an annonce, it counts for all admins of that boutique”):

You check target_boutiques and target_roles.

If one of the admins of a boutique reads it, you can programmatically mark it as read for all other admins of that boutique.

This allows efficient tracking of which notifications are still new per user while keeping a history of everyone’s reads.
